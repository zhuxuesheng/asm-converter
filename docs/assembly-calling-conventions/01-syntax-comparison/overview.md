# 汇编语法对比概述

> 了解Go Plan9、Intel和AT&T三种主流汇编语法的历史背景、设计理念和适用场景

## 引言

汇编语言作为最接近机器码的编程语言，在不同的历史时期和技术生态中发展出了多种语法风格。对于汇编语言开发者而言，理解这些语法差异不仅有助于阅读和编写不同环境下的汇编代码，更能深入理解各种工具链和操作系统的设计哲学。

本章节将介绍三种最常见的汇编语法：

| 语法 | 代表工具 | 主要使用场景 |
|------|----------|--------------|
| **Go Plan9** | Go编译器 | Go语言运行时和标准库 |
| **Intel** | NASM, MASM, YASM | Windows开发、独立汇编项目 |
| **AT&T** | GAS (GNU Assembler) | Linux/Unix系统、GCC工具链 |

---

## 历史背景

### Go Plan9 汇编

#### 起源：Plan 9 操作系统

Plan 9汇编语法源自贝尔实验室在1980年代末开发的Plan 9操作系统。Plan 9是Unix的精神继承者，由Unix的原始创造者Ken Thompson和Rob Pike等人设计，旨在探索分布式计算的新范式。

```
时间线：
1987年 - Plan 9项目启动于贝尔实验室
1992年 - Plan 9首次公开发布
2009年 - Go语言发布，继承Plan 9汇编语法
2012年 - Go 1.0发布，Plan 9汇编成为Go生态标准
```

#### 设计理念

Plan 9汇编的设计理念是**跨平台抽象**。与传统汇编语法不同，Plan 9汇编试图在不同CPU架构之间提供统一的语法风格，通过引入伪寄存器（pseudo-registers）来抽象底层硬件差异。

**核心特点**：
- **伪寄存器系统**：FP（帧指针）、SP（栈指针）、SB（静态基址）、PC（程序计数器）
- **统一的指令命名**：跨架构使用相似的指令助记符
- **与Go运行时深度集成**：支持Go的栈增长、垃圾回收等机制

#### 在Go语言中的演进

Go语言选择Plan 9汇编有其历史原因——Go的创造者Rob Pike和Ken Thompson正是Plan 9的核心开发者。这种选择带来了独特的优势：

```go
// Go函数声明
func Add(a, b int64) int64

// 对应的Plan9汇编实现 (amd64)
TEXT ·Add(SB), NOSPLIT, $0-24
    MOVQ    a+0(FP), AX
    ADDQ    b+8(FP), AX
    MOVQ    AX, ret+16(FP)
    RET
```

> **参见**: [Go Plan9 汇编详解](go-plan9.md) 了解完整的语法规范

### Intel 汇编语法

#### 起源：Intel处理器文档

Intel汇编语法直接源自Intel公司的处理器技术文档。从8086处理器开始，Intel就在其官方手册中使用这种语法风格来描述指令集。

```
时间线：
1978年 - Intel 8086处理器发布，确立基本语法风格
1981年 - IBM PC使用8088处理器，Intel语法成为PC汇编标准
1989年 - MASM 5.1成为DOS时代的主流汇编器
1996年 - NASM项目启动，提供开源的Intel语法汇编器
2001年 - YASM项目启动，NASM的现代化重写
```

#### 设计理念

Intel语法的设计理念是**直观可读**。其语法结构接近自然语言的表达方式，目标操作数在前，源操作数在后，符合"将值移动到目标"的直觉。

**核心特点**：
- **目标在前**：`MOV destination, source`
- **清晰的内存访问**：使用方括号 `[address]` 表示内存操作
- **无需操作数大小后缀**：通过寄存器名或显式声明确定大小
- **丰富的寻址模式表示**：`[base + index*scale + displacement]`

#### 主要实现

| 汇编器 | 特点 | 平台 |
|--------|------|------|
| **MASM** | Microsoft官方，与Visual Studio集成 | Windows |
| **NASM** | 开源、跨平台、语法严格 | 跨平台 |
| **YASM** | NASM兼容，支持更多目标格式 | 跨平台 |
| **FASM** | 自举汇编器，语法独特 | 跨平台 |

```nasm
; Intel语法示例 (NASM)
section .text
global add_numbers

add_numbers:
    mov     rax, rdi        ; 第一个参数 -> rax
    add     rax, rsi        ; 加上第二个参数
    ret
```

> **参见**: [Intel 汇编详解](intel.md) 了解完整的语法规范

### AT&T 汇编语法

#### 起源：Unix和PDP-11

AT&T汇编语法的历史可以追溯到1970年代的Unix操作系统和PDP-11小型机。当时AT&T贝尔实验室的工程师们为Unix开发了这种汇编语法风格。

```
时间线：
1971年 - Unix在PDP-11上运行，确立AT&T语法基础
1987年 - GNU Assembler (GAS) 发布，AT&T语法进入GNU生态
1992年 - Linux采用GCC/GAS工具链，AT&T语法成为Linux标准
1999年 - GAS添加 .intel_syntax 指令，支持Intel语法
```

#### 设计理念

AT&T语法的设计理念是**明确性和一致性**。每个操作数都有明确的前缀标识其类型，指令后缀明确指定操作数大小，这种设计减少了歧义。

**核心特点**：
- **源在前**：`movq %source, %destination`
- **寄存器前缀**：所有寄存器以 `%` 开头
- **立即数前缀**：所有立即数以 `$` 开头
- **大小后缀**：`b`(byte)、`w`(word)、`l`(long)、`q`(quad)
- **内存寻址格式**：`displacement(%base, %index, scale)`

#### 在GNU工具链中的地位

AT&T语法是GNU工具链的原生语法，这意味着：

- GCC生成的汇编代码默认使用AT&T语法
- GDB反汇编默认显示AT&T语法
- Linux内核源码中的汇编使用AT&T语法

```gas
# AT&T语法示例 (GAS)
.text
.globl add_numbers

add_numbers:
    movq    %rdi, %rax      # 第一个参数 -> rax
    addq    %rsi, %rax      # 加上第二个参数
    ret
```

## 适用场景

### Go Plan9 汇编适用场景

| 场景 | 说明 | 示例 |
|------|------|------|
| **Go运行时开发** | 实现Go运行时的底层功能 | 调度器、内存分配器 |
| **Go标准库优化** | 为标准库提供高性能实现 | crypto、math包 |
| **Go程序性能热点** | 优化Go程序的关键路径 | 编解码、哈希计算 |
| **跨平台Go汇编** | 编写可在多架构运行的汇编 | 通用算法实现 |

**典型用户**：
- Go语言核心开发者
- 需要极致性能的Go应用开发者
- Go运行时研究者

**优势**：
- 与Go类型系统和调用约定无缝集成
- 支持Go的栈增长机制
- 可以直接访问Go的运行时功能

**限制**：
- 仅在Go生态系统内使用
- 学习资源相对较少
- 调试工具支持有限

## 关键差异概览

### 语法元素对比

| 元素 | Go Plan9 | Intel | AT&T |
|------|----------|-------|------|
| **操作数顺序** | 源, 目标 | 目标, 源 | 源, 目标 |
| **寄存器表示** | AX, BX | rax, rbx | %rax, %rbx |
| **立即数表示** | $123 | 123 | $123 |
| **内存访问** | 0(SP) | [rsp] | (%rsp) |
| **大小指定** | MOVQ, MOVL | mov (推断) | movq, movl |

### 等效指令示例

将寄存器BX的值加到AX上（64位模式）：

```
Go Plan9:  ADDQ BX, AX
Intel:     add  rax, rbx
AT&T:      addq %rbx, %rax
```

将立即数42存入内存地址[RSP+8]：

```
Go Plan9:  MOVQ $42, 8(SP)
Intel:     mov  qword [rsp+8], 42
AT&T:      movq $42, 8(%rsp)
```

### 多语法能力的重要性

作为汇编语言专家，掌握多种语法是必要的：

1. **阅读能力**：能够阅读任何语法的汇编代码
2. **工具适应**：不同工具可能使用不同语法
3. **跨平台工作**：不同平台有不同的语法偏好
4. **文档理解**：官方文档可能使用特定语法
